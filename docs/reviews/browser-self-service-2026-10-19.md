# Self-service verification procedure

Use your own disposable approved target, scoped service identity, private PostgreSQL/S3-compatible
services and production-profile Kubernetes execution provider. Follow the installation and browser
user guides; never treat this procedure as a capacity certification.

1. Create an API definition from a consumer requirement and validate it.
2. Save an immutable version and trigger it with an idempotency key.
3. Observe real runner progress, complete objective outcomes and digest-verified private evidence.
4. Import a reviewed browser journey, start with one browser/iteration, then verify page and journey measurements.
5. Exercise failing assertions, cancellation, cross-team denial and control-plane restart recovery.
6. Verify a failure stops all runner handles before freeing capacity.
7. Confirm operator user/duration ceilings, blocked cross-origin redirects and objective unit/percentile validation.
8. For rate-based runs, check a steady-state window separately from the whole-profile mean.

Record installation-specific run IDs, private screenshots and credentials outside source control.
